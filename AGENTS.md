# Aturan Kerja PostPocket

Repo ini dikerjakan berdua oleh **Kall** ([@HaikalFaruq](https://github.com/HaikalFaruq)) di frontend dan **Bintang** ([@bintangfabian](https://github.com/bintangfabian)) di backend, sering dengan bantuan AI agent. Aturan di bawah berlaku untuk kita berdua dan untuk agent apa pun yang dipakai.

Sumber kebenaran produk ada di [PRD](docs/prd/PRD-PostPocket.md). AI agent wajib membaca file ini sampai habis sebelum mengubah apa pun, lalu membaca panduan sesuai peran orang yang menjalankannya (bagian 5).

## 1. Tanpa atribusi AI

Commit, PR, issue, dan komentar tercatat atas nama orang yang menjalankannya. Jangan tulis atribusi AI dalam bentuk apa pun:

- Trailer seperti `Co-Authored-By: Claude <noreply@anthropic.com>`, `Claude-Session: …`, `Assisted-by: …`, dan trailer sejenis dari agent lain (Codex, Copilot, Cursor, Gemini, Aider, Devin, Jules, Amp, Warp, dan seterusnya).
- Footer seperti `🤖 Generated with Claude Code` atau `Generated by Copilot`, serta link sesi agent.
- Agent atau bot AI sebagai author atau committer, misalnya `claude[bot]`, `Copilot`, `Cursor Agent`, `devin-ai-integration[bot]`, atau nama berakhiran `(aider)`. Commit selalu memakai identitas git kamu sendiri.

Kalau agent kamu menambahkan atribusi otomatis, matikan di setting-nya. Untuk Claude Code sudah dimatikan lewat `.claude/settings.json` di repo ini.

Aturan ini dicek berlapis, jadi pelanggaran berhenti sebelum masuk `main`:

| Lapis | Yang dicek | Kapan |
| --- | --- | --- |
| `.githooks/commit-msg` | Pesan commit | Setiap `git commit` |
| `.githooks/pre-push` | Author, committer, dan pesan semua commit yang di-push | Setiap `git push` |
| Workflow `No AI attribution` | Sama seperti pre-push, plus judul dan deskripsi PR | Setiap PR dan push ke `main` |
| Branch protection `main` | Hanya menerima commit yang lolos cek `no-ai-attribution`, termasuk dari admin. Force push dan hapus `main` diblokir | Di GitHub |

Hook aktif otomatis setelah `pnpm install` (script `prepare`). Tanpa pnpm, aktifkan sekali per clone:

```sh
git config core.hooksPath .githooks
```

Kalau ditolak, perbaiki commit-nya. Jangan lewati hook dengan `--no-verify`, karena CI tetap menolaknya.

| Kasus | Perintah |
| --- | --- |
| Pesan commit terakhir | `git commit --amend`, lalu hapus atribusinya |
| Author commit terakhir | `git commit --amend --reset-author --no-edit` |
| Commit yang lebih lama | `git rebase -i origin/main`, tandai `reword` atau `edit`, lalu `git push --force-with-lease` ke branch fitur kamu, tidak pernah ke `main` |

Semua pola ada di `scripts/check-no-ai.sh` dan contohnya di `scripts/test-check-no-ai.sh`. Kalau ada agent baru yang lolos, tambahkan pola dan contohnya lewat PR.

## 2. Pasangan jadi co-author

Setiap commit menyertakan pasangan sebagai co-author, supaya begitu PR-nya di-merge kita berdua dapat achievement **Pair Extraordinaire**. Ini trailer manusia, jadi tidak ikut ditolak cek di bagian 1.

| Yang commit | Trailer di akhir pesan commit |
| --- | --- |
| Kall | `Co-authored-by: Bintang Fabian Putra <47806878+bintangfabian@users.noreply.github.com>` |
| Bintang | `Co-authored-by: Muhammad Haikal Faruq <50310521+HaikalFaruq@users.noreply.github.com>` |

- Taruh trailer di baris paling akhir, dipisah satu baris kosong dari isi pesan.
- Pakai email noreply di atas supaya co-author pasti terhubung ke akun GitHub masing-masing.
- Merge PR pakai **Create a merge commit** (`gh pr merge --merge`). Squash dan rebase dimatikan di repo ini, karena di Tookthel PR yang di-squash tidak memberi badge.

## 3. Pesan commit dan PR harus bisa dilanjutkan

Siapa pun yang baca harus langsung paham apa yang berubah dan bisa lanjut dari situ.

**Commit:** format Conventional Commits dalam Bahasa Indonesia (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`). Judul maksimal 72 karakter. Isi pesan menjelaskan apa yang berubah dan kenapa.

**PR:** deskripsi mengikuti template `.github/pull_request_template.md`.

```markdown
## Apa yang berubah
## Kenapa
## Sudah dicek
## Selanjutnya
```

Bagian **Selanjutnya** berisi langkah berikutnya, hal yang belum beres, atau keputusan yang perlu diambil pasangan. Jangan dikosongkan.

## 4. Alur kerja

Branch (`feat/…`, `fix/…`, `docs/…`) → PR → review pasangan → merge, satu PR untuk satu topik. Jangan push langsung ke `main`.

Setiap mulai sesi, termasuk sesi AI agent:

1. Sinkron dulu: `git switch main && git pull`.
2. Pastikan hook aktif: `git config core.hooksPath` harus mengeluarkan `.githooks`.
3. Buka checklist peranmu (bagian 5), ambil item pertama yang belum dicentang, lalu kerjakan lewat alur di atas.
4. Centang item itu di PR yang sama.

## 5. Peran dan area kode

| Area | Pemilik | Isi |
| --- | --- | --- |
| `apps/web/` | Kall | Nuxt: semua halaman, kartu foil 3D, editor surat, Pocket, TV, Booth, IndexedDB |
| `supabase/migrations/` | Bintang | Skema SQL dan RLS |
| `supabase/functions/` | Bintang | Edge Functions: letters, publish, og |
| `docs/api/openapi.yaml` | Bintang menulis, Kall me-review | Kontrak API antara frontend dan backend |
| `packages/presets/` | Kall | Preset desain dalam JSON. Backend hanya menyimpan id-nya |
| `docs/` | Berdua | PRD, panduan peran, catatan referensi, lisensi aset |

- **Agent untuk Bintang** bekerja sebagai backend engineer. Mulai dari [docs/backend.md](docs/backend.md): cakupan, keputusan yang menunggu, checklist per sprint, data model, endpoint, dan syarat keamanan.
- **Agent untuk Kall** bekerja sebagai frontend engineer. Mulai dari [docs/frontend.md](docs/frontend.md): cara menjalankan, aturan token dan preset, komponen bersama, dan checklist per sprint.
- Kontrak dulu, kode kemudian. Endpoint baru atau perubahan bentuk data masuk ke `docs/api/openapi.yaml` lewat PR yang di-review pasangan, baru diimplementasikan. Frontend boleh jalan dengan mock dari kontrak itu.
- Jangan mengubah area pasangan tanpa bilang dulu. Kalau butuh perubahan di sana, tulis di bagian **Selanjutnya** PR kamu.
- Secret (service role key, token) tidak pernah di-commit. Pakai `.env` dan sediakan `.env.example`.

## 6. Perintah

Butuh Node 24 (`.nvmrc`) dan pnpm 9. Semua perintah dijalankan dari root repo.

| Perintah | Fungsi |
| --- | --- |
| `pnpm install` | Pasang dependensi dan aktifkan hook git |
| `pnpm dev` | Server development frontend (`apps/web`) |
| `pnpm lint` | ESLint (warning dianggap gagal) dan Prettier |
| `pnpm typecheck` | Cek tipe semua package |
| `pnpm test` | Unit test Vitest semua package |
| `pnpm test:e2e` | E2E Playwright di build production (Android, iPhone, desktop) |
| `pnpm check` | `lint`, `typecheck`, dan `test` sekaligus |
| `scripts/check-no-ai.sh --revs origin/main..HEAD` | Cek atribusi AI di commit yang belum masuk `main` |
| `scripts/test-check-no-ai.sh` | Uji pola cek atribusi AI, wajib lolos setelah polanya diubah |

Sebelum push, pastikan `pnpm check` dan `pnpm test:e2e` lolos. Perilaku baru wajib disertai test: logika di unit test, alur pengguna di E2E. CI menjalankan semuanya di setiap PR (workflow `Web` dan `No AI attribution`).

Siapa pun yang membuat `supabase/` wajib menambahkan perintahnya ke tabel ini, beserta job CI-nya.

## 8. Aturan produk

- **Tiru dulu, poles nanti.** Layout, urutan langkah, dan interaksi dibuat semirip mungkin dengan referensi di PRD.
- Aset visual dari web referensi (kantong, stiker, ilustrasi, desain TV) tidak boleh disalin ke repo. Catat sumber dan lisensi setiap aset di `docs/assets.md`.
- Warna, radius, font, dan bayangan adalah design token. Pilihan desain (kertas, foil, kantong, stiker, bingkai, filter) adalah preset JSON di `packages/presets/`, bukan hardcode di komponen.
- Bukan target rilis 1: aplikasi native, editor ilustrasi sendiri, pembayaran, fitur sosial, kolaborasi real-time.
